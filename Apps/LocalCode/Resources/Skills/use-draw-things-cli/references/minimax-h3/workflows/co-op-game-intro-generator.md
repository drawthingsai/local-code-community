# Co-op game intro

Use for a two-player game-menu concept progressing from character selection to
entering a game world. Use the shared [production workflow](../production.md) for
assets and assembly, and [H3 prompting](../prompting.md) for generation.

## Establish the menu and identities

Use the provided game title, player names, character references, and requested
visual style. Keep a coordinated menu framework: two clearly distinct players,
stable player positions, consistent type and interface colors, readable selection
states, and an obvious confirmation action. Carry recognizable facial, costume,
and silhouette traits from selection into the game-world scene.

Compose one full-frame menu image. For a landscape layout, put both characters at
center, player cards at upper left, the main menu at right, and a decorative strip
along the bottom. Lead the eye from player cards to characters to menu to the
primary “CONTINUE” action. Keep clear space behind interface text. Use 16:9 unless
the brief specifies another format, then adapt the layout while retaining hierarchy.

Use a coordinated palette of roughly five main colors: background, interface body,
text, functional accent, and warning/exit color. Carry it through cards, buttons,
equipment, loading indicators, and the game world. The requested medium controls
character rendering, surfaces, icons, typography, and animation style together.

Keep player one on the left and player two on the right, with the supplied names
bound to the correct faces. Preserve distinctive hair, glasses, facial proportions,
and body silhouettes when translating identities into the visual style. For the
equipment sequence below, give player one a light, articulated claw and player two
a heavy mechanical fist; retain requested character traits and equipment overrides.

Specify every visible menu string. A starting set is “PLAYER 1,” “PLAYER 2,” the
two supplied names, “READY,” “START NEW GAME,” “CONTINUE,” “SETTINGS,” and “EXIT GAME.”
Use the brief's language and copy. For an image-only request, deliver the menu image.
For video, use that clean full-frame image as the opening anchor.

## Preserve the progression

A fifteen-second intro can use this beat plan:

| Time | Event |
| --- | --- |
| 0–2 s | Establish the main menu and both players |
| 2–4 s | Player one configures an arm attachment |
| 4–7 s | Player two configures the heavier arm attachment |
| 7–8.5 s | Confirm both selections |
| 8.5–10 s | Transition through loading |
| 10–15 s | Enter the game world with the selected characters |

During player one's configuration, push toward the right arm while keeping player
two visible. Slide the equipment panel into place, move its selection highlight,
unfold the claw, lock each joint, and illuminate its accent lights. During player
two's configuration, move across the pair and use slower, heavier assembly and
lock-in motion. Keep the already-equipped player visible in the background.

Give confirmation a clear state change, then let loading resolve into the game
world with both selected identities and attachments intact. Pair hover, selection,
joint locking, and heavy impacts with appropriate sound cues. Adapt beat times to
the actual clip duration; for a shorter clip, choose a complete part of the sequence.

Write the final technical prompt in H3's required structure and English descriptive
prose, preserving the requested language for visible copy and dialogue.

Review both identities, equipment continuity, player positions, every readable
label, selection-state transitions, and the entry into the world. Deliver the
result as a game-intro concept animation; it does not implement a playable game.
